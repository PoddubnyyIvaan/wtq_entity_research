# Постановка задачи — исследование перевода именованных сущностей и лексики WikiTableQuestions (EN → RU)

Общая рамка для всех четырёх экспериментов. Каждый эксперимент независим,
его результаты не смешиваются с другими до итогового сравнения.

---

## 1. Контекст и данные

Рабочая директория содержит три репозитория/пакета:

```text
WikiTableQuestions/   # датасет (read-only)
wtq-translator/       # production translator (read-only, не запускается)
wtq_entity_research/  # вся исследовательская работа
```

`WikiTableQuestions` (WTQ): 22 009 вопросов, 2 108 таблиц, 376 917 ячеек.
Связи: `data/training.tsv (id, utterance, context, targetValue)` →
`csv/N-csv/M.csv` ↔ `page/N-page/M.json` (тот же N/M); существующая CoreNLP
NER-разметка в `tagged/*-tagged/*.tagged`. `page/*.json` содержит
`title/url/tableIndex/revision`; article context — `*.html` (~80 КБ/страницу).

### Общий sample

```text
n = 200, seed = 42
strata: PERSON 30, SURNAME 15, LOCATION 25, ORGANIZATION 20, SPORTS_TEAM 20,
        EVENT_WORK 25, MULTI_WORD 20, SHORT_AMBIGUOUS 20, FALSE_POSITIVE 15, UNKNOWN 10
dev:  e001–e020
eval: e021–e200   (eval не используется для подгонки методов)
```

Canonical sample: `wtq_entity_research/samples/sample200.jsonl`;
обязательные синтетические кейсы отдельно:
`Smith, Smyth, New York, London, George, Arsenal, Washington` (не смешивать
с WTQ-статистикой).

## 2. Общие ограничения

1. Оба репозитория — только чтение; production translator не запускается.
2. Все артефакты — только в `wtq_entity_research/` (каждый эксперимент —
   своя подпапка со скриптами/кэшем/результатами).
3. Большие файлы — только программная потоковая обработка; в контекст агента
   не загружать.
4. Свой NER не запускать — использовать существующую CoreNLP разметку.
5. Внешние API: Wikidata/Wikipedia с rate-limits (≥0.5 s, backoff 429);
   LLM — только локальная Ollama `qwen2.5:3b` (при доступности), для
   генерации в некоторых экспериментах запрещена (см. режимы).
6. Метрики: coverage/agreement/identity-verification — НЕ accuracy;
   human gold на 40 reused manual cases; LLM-оценки не gold.
7. Round-trip `EN→RU→EN exact` — только диагностика.
8. Raw responses, кэши, промпты, версии промптов, seed — сохранять.
9. `NO_MATCH`/`MULTIPLE`/ambiguous — не считать ошибкой и не удалять.

## 3. Классы значений WTQ

```text
COMMON_WORD | NAMED_ENTITY | NUMBER | DATE | JUNK | UNKNOWN
```

Ожидания по архитектурным ролям: common words → словари; entities →
ParaNames/Wikidata/Wikipedia (identity); numbers/dates → immutable;
junk → preserve verbatim.

## Эксперимент 1 — Baselines без LLM (Wikidata/Wikipedia/транслитерация/JRC-Names + QC)

**Вопросы**: какие типы сущностей в WTQ; нужен ли контекст; полезны ли
Wikidata/Wikipedia/JRC-Names; транслитерация; какие QC-метрики надёжнее.

1. Профилирование WTQ (потоково).
2. Stratified sample (выше).
3. Exp0 copy baseline; Exp2 Wikidata resolver (search → WP fallback →
   P31/header-ранжирование → RU form `sitelink > label > alias`); Exp3
   сравнение RU-источников; Exp4 транслитерация+словарь; Exp5 JRC-Names;
   Exp6 QC (round-trip, normalized match, entity identity, TM-consistency).
4. Decision rules → статусы VERIFIED/ACCEPTABLE_WITHOUT_ENTITY_ID/AMBIGUOUS/
   SUSPICIOUS/UNRESOLVED/NA_ENTITY_QC + human контроль 40 примеров.

**Ключевые артефакты**: `data_profile/`, `samples/`, `results/exp0–exp6`,
`report.md`, `environment.md`.

## Эксперимент 2 — LLM: контекстные режимы и LLM judge (qwen2.5:3b)

**Вопросы**: помогает ли header/row/question/title; минимальный контекст;
harmful substitutions; снижает ли LLM-judge false positives/rate правил.

1. Smoke test (перевод, JSON, context sensitivity) — до pilots.
2. Pilot 5 → Pilot 20 → full 200×4 режимов A(cell)/B(+column)/C(+row)/
   D(+row+column+question+title).
3. Единый JSON-схема ответа (`is_entity, entity_type, interpretation,
   confidence — self-reported, needs_review`); prompt versioned (v1→v2).
4. LLM ≠ ground truth для QID: interpretation сверяется с Wikidata evidence.
5. Experiment 6E: judge оценивает уже полученные переводы (semantic_ok,
   entity_ok, context_ok, harmful_substitution, needs_review + reason),
   оценивается на тех же 40 manual-кейсах.
6. Latency (mean/median/p95), Ollama без гарантии детерминизма (temperature=0).

**Ключевые артефакты**: `results/exp1_llm_context*.jsonl`, `exp6e_llm_judge*`,
`prompts/exp1_v2.txt`, `judge_v1.txt`, `report/llm_experiment_report.md`.

## Эксперимент 3 — ParaNames

**Вопросы**: покрывает ли ParaNames WTQ-сущности; даёт ли правильную русскую
surface form; можно ли ставить первым lookup-слоем перед Wikidata.

1. Официальный релиз (bltlab/paranames v2024.05.07.0, MIT; Wikidata dump
   2024-03-13); индекс EN-key → RU + QID → RU (identity-путь).
2. Никаких blind replacements: сохраняются кандидаты, QID, тип, counts.
3. Variant A (dictionary only) и Variant B (context reranking: LLM выбирает
   ТОЛЬКО candidate_id или NO_MATCH, генерация запрещена).
4. RU-collisions (одинаковая RU у разных QID), identity через QID,
   harmful substitutions классифицируются:
   IDENTITY_ERROR / WRONG_RUSSIAN_FORM / AMBIGUOUS / NO_MATCH / CORRECT.

**Ключевые артефакты**: `experiments/paranames/` (DATASET_INFO.md,
PARANAMES_REPORT.md, paranames_results.jsonl, scripts/, raw/).

## Эксперимент 4 — Готовые EN→RU словари (4 независимых)

Wikidict (WD interwiki DSL), Wiktionary (Buchmeier DSL .dz), OpenRussian
(обратный индекс по EN-глоссам), Statistical (full 56 624 + filtered 4 096,
count/probability). Каждый — свой индекс/кэш/результаты/отчёт; никакой LLM
в baseline; reranking — отдельный optional шаг.

1. Отдельные эксперименты per dictionary (режимы A–D сохраняют candidate
   set, не выбирают автоматически).
2. Классификация occurrences: COMMON_WORD/NAMED_ENTITY/NUMBER/JUNK;
   NO_MATCH у entities — не dictionary failure.
3. Только после отдельных экспериментов: union/intersection/agreement,
   таблица сравнения, сравнение с entity-экспериментами.
4. Agreement ≠ correctness; union ≠ автоматический выбор.

**Ключевые артефакты**: `experiments/dictionaries/{wikidict,wiktionary,
openrussian,statistical}` + `COMPARISON_REPORT.md`.

## Единые метрики (по выборке, с указанием n)

coverage · candidate coverage · RU-form coverage · identity verified ·
agreement (≠ correctness) · manual correctness (40) · ambiguity/multi rate ·
harmful substitution rate · needs-review rate · consistency · latency/cost.

## Критерий успеха

Воспроизводимость (seed/версии/кэши/промпты), неизменность репозиториев,
незамешанные результаты, отсутствие выдуманных данных, явные BLOCKED
фиксации при недоступных ресурсах.
