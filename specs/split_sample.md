# Спецификация: sample200.jsonl → 6 равных частей + запуск частей в exp2_wikidata

- Тип спецификации: **Pipeline** + **CLI-расширение** (детерминированный
  разрез файла-источника + минимальное расширение CLI существующего
  эксперимента, чтобы часть подавать в него как вход и изолировать кэш/лок).
- ID: `split_sample`
- Статус: утверждена (зафиксированы решения пользователя в разделе «Input»).

## Motivation

Полный прогон `scripts/exp2_wikidata.py` по `samples/sample200.jsonl` (44237
записей, ~2–3 HTTP-запроса на ячейку → ≈99k запросов при прямом счёте) упирается
в потолок Wikimedia для неавторизованных клиентов: **200 req/min на один
внешний IP, суммируясь по всем хостам** (wikidata.org + en.wikipedia.org,
см. docstring exp2_wikidata.py). На одной машине честный полный прогон на 200 rpm
длится ~8 часов и деградирует при любой ошибке.

Решение пользователя: разрезать выборку на **6 равных частей** и гнать части
**параллельно с 6 разных машин**, каждая со своим внешним IP, на полном лимите
`--workers 3 --rpm 200`. Суммарная скорость при этом 6×200 rpm, но лимит
считается на IP, поэтому нарушений нет, а время прогона сокращается до
~1.5–2 часов. Для этого нужны:

1. Детерминированный скрипт разреза (части не пересекаются, размеры отличаются
   не более чем на 1 строку, порядок и `example_id` внутри части не меняются).
2. Подача части в `exp2_wikidata.py` (`--input`) и изоляция кэша/лока на часть
   (`--cache-name`): иначе все машины пишут в один `cache/wikidata.json` с общим
   `flock` и блокируют друг друга при любом шаринге файловой системы, а при
   параллельных прогонах на одном FS затирают кэш.

## Input

### `samples/sample200.jsonl` (файл-источник для разреза)
- JSONL, UTF-8, LF; каждая физическая строка — ровно один объект
  (15 ключей, schema канонического sample200, см. specs/entities_to_sample200.md).
- Заголовка нет. Текущий объём: **44237 непустых строк** (проверено потоковым
  парсингом). Гарантируется, что каждая строка парсится `json.loads`.
- Разрез выполняется **байт-в-байт по физическим строкам** без пересоздания
  JSON: часть — это непрерывный срез строк исходного файла, поэтому любой
  валидный вход автоматически даёт валидные части.

### Решения пользователя
1. Количество частей — строго **6** (по умолчанию; параметризуется CLI).
2. Части **непересекающиеся и непрерывные** (не вперемешку), размеры равные
   «насколько возможно»: `|sizes[i] − sizes[j]| ≤ 1`.
3. Расчёт размера: `base, rem = divmod(n, parts)`; первые `rem` частей получают
   `base+1` строк, остальные — `base`. Для n=44237, parts=6 → пять частей по
   7373 и одна по 7372 (5×7373+7372=44237).

## Processing (алгоритм сплиттера)

1. Входной путь: первый позиционный аргумент, по умолчанию
   `samples/sample200.jsonl`. Число частей: второй позиционный аргумент, по
   умолчанию 6.
2. **Проход 1** — подсчёт строк во входе (`sum(1 for _ in f)`); пустой вход →
   `ValueError` (exit 1).
3. Расчёт размеров частей по формуле из «Input».
4. Проверка `1 ≤ parts ≤ n` (иначе были бы пустые части) → `ValueError`.
5. Открыть одновременно `parts` исходящих файлов `out_dir/<stem>_part<i>_…`:
   имя = имя входа с вставкой `_part<K>` перед расширением:
   `samples/sample200.jsonl` → `samples/sample200_part1.jsonl` …
   `samples/sample200_part6.jsonl`.
6. **Проход 2** — потоковый разрез: каждый прочитанный байт-срез строки пишется
   в текущую часть; при исчерпании размера переключаемся на следующую часть.
   Первая строка каждой части и последняя строка каждой части разбираются
   `json.loads` только ради `example_id` для сводки (ошибка парсинга не
   критична — в сводке выводится `<n/a>`).
7. Контроль целостности: количество записанных строк каждого файла обязано
   совпасть с расчётными размерами; общее число прочитанных строк обязано
   совпасть с числом прохода 1 (защита от изменения файла между проходами).
8. Сводка в stdout: общее число строк, для каждой части — имя файла, число
   строк, первый и последний `example_id`. Exit code 0.

## Output

### Файлы-назначения
- `samples/sample200_part1.jsonl` … `samples/sample200_part6.jsonl` — части
  исходного файла, строки скопированы байт-в-байт, порядок сохранён.
- Суммарное число строк по частям = числу строк источника. Никаких других
  файлов/каталогов скрипт не трогает.

### CLI
```
python3 scripts/split_sample.py [INPUT_JSONL] [N_PARTS]
```
- `INPUT_JSONL` — по умолчанию `samples/sample200.jsonl`;
- `N_PARTS` — по умолчанию `6`.

## Data Flow

```
samples/sample200.jsonl ──разбор (2 прохода)──▶ sample200_part1..6.jsonl
                                                   │
                                                   └──▶ (входы запусков exp2 на 6 машинах)
```
Последующие запуски:
```
scripts/exp2_wikidata.py --input samples/sample200_partK.jsonl --cache-name wikidata_partK
        └──▶ cache/wikidata_partK.json  (свой кэш+flock на каждую часть)
        └──▶ results/exp2_wikidata*.jsonl (_stats.json) — на своей машине
```
Другие сервисы и хранилища не затрагиваются. Части disjoint → между машинами
нет общих URL-ов, кэши не пересекаются по содержимому и могут объединяться
после прогона простой конкатенацией JSON-объектов при желании.

## Error Handling

| Failure mode | Поведение |
|---|---|
| Входной файл не существует | `FileNotFoundError` → сообщение в stderr, exit code 2 |
| Вход пуст (0 строк) | `ValueError` → stderr, exit code 1 |
| `N_PARTS` не число / < 1 / > строк входа | `ValueError` → stderr, exit code 1 |
| Число прочитанных строк ≠ числу строк прохода 1 | `RuntimeError` → stderr, exit code 1 (файл менялся между проходами) |
| Ошибка записи части | проброс исключения, exit code 1 |
| Неверный `--input`/`--cache-name` в exp2 | в `exp2_wikidata.py`: отсутствующий вход — сообщение в stderr, exit 2; нечисловой `--workers`/`--rpm`/`limit` — прежнее поведение `ValueError` |

## Testing

Проверки выполняются контейнерно при верификации (pytest в репо нет):

1. **Полнота**: сумма строк шести частей = 44237; каждая часть — непрерывный
   срез: `partK` совпадает со строками исходника с
   `sum(sizes[:K-1])` по `sum(sizes[:K])-1` включительно.
2. **Размеры**: для n=44237 и parts=6 → `[7373]*5 + [7372]`; |diff| ≤ 1.
3. **Валидность**: каждая строка каждой части парсится `json.loads`.
4. **Схема**: каждый объект части несёт `example_id`, первый объект part1 —
   `e00001`, последний объект part6 — `e44237`.
5. **Затрагиваются только части**: в каталоге `samples/` не появляется других
   новых файлов.
6. **Отсутствие потерь**: `part1..part6` в конкатенации дают байт-в-байт исходный
   файл.
7. **CLI exp2 (offline)**: `parse_args` возвращает корректные значения для
   `["--workers","3","--rpm","200","--input","samples/sample200_part2.jsonl",
   "--cache-name","wikidata_part2"]` и для прежних аргументов
   `["200"]` (совместимость: `limit=200`, `workers=3`, `rpm=200`,
   input=canonical, cache=wikidata).

## Dependencies

- Python 3.10+ (аннотации), стандартная библиотека `json`, `pathlib`, `sys`.
- Внешние пакеты не требуются; venv не нужен (соответствует environment.md).
- Зависимости на другие модули репозитория: нет. CLI-расширение меняет только
  `scripts/exp2_wikidata.py` и сохраняет контракт `Http` и `common.py`
  без изменений.

## Exceptions

- Части непрерывные, а не страйпнутые: перед пользователем, решение от
  2026-09-22 «разделить на 6 равных частей» без требования страйпа; непрерывный
  срез проще проверяется контрольными суммами и воспроизводим.
- Разница размеров частей ≤ 1 строка, а не «ровно одинаковые» — 44237 не
  делится на 6 нацело (44237 = 6×7372 + 5).
- Скрипт не пересоздаёт JSON-объекты, а копирует физические строки: части
  гарантированно валидны при валидном входе и не искажают форматирование.
