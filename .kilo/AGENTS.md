
# Основные правила

1. Явно проговаривай допущения.

2. Если что-то непонятно или имеет несколько решений спроси.
3. Возражай если видишь более простое/лаконичное решение.
4. При путанице останавливайся, говори что не понятно и спрашивай что делать.
5. Не добавляй функционал не требующийся в задаче.
6. Никаких абстракций для одноразового кода
7. Не делай обработку ошибок для невозможных сценариев.
8. Хороший код - это короткий код, который решает поставленную задачу.
9.  Строго запрещено менять поведение уже написанные функции, которые используются в других сервисах и эндпоинтах.
10. Если видишь мертвый код, сообщи о нем, но не удаляй без разрешения.
11. Разбивай задачу на подзадачи так, чтобы изменения затрагивали не больше 1-2 файлов за раз
12. После решения задачи и  внесения изменений сохраняй краткое описание внесенных изменений в CHENGELOG.md 

## Экономия токенов

- Не читай файлы целиком без необходимости.
- Сначала используй `rg`, `grep`, `glob`, точечные чтения.
- Для больших файлов используй `head -n 100` или чтение нужного диапазона.
- Не выводи полные логи.
- Не вставляй большие куски кода без необходимости.
- Перед чтением файла оцени размер через `ls -lh` или `wc -l`, если это дешево.
- Для тестов используй `pytest -q --tb=short --maxfail=1`.
- Для git используй короткие выводы: `git log --oneline -n 20`, `git diff --stat`.
- Не выполняй `python3` и `pip install` без необходимости.
- Избегай чтения `.env`, секретов, больших бинарных файлов, логов и артефактов сборки.
- Если результат можно показать кратко, показывай кратко.
