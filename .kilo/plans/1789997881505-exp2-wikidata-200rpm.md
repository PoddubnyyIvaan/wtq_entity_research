# План: эффективные 200 req/min к Wikimedia для exp2

## Цель
Разогнать `scripts/exp2_wikidata.py` до **контролируемых 200 запросов/мин** к API
Wikidata/Wikipedia (жёсткий потолок неавторизованного клиента с корректным UA),
не рискуя 429/баном. По умолчанию — 200 (решение пользователя), параметр `--rpm`
позволяет снижать.

## Контекст: что уже сделано и работает (проверено чтением кода)
- `scripts/common.py::Http` потокобезопасен: глобальный гейт пауз (старты не чаще
  `min_interval`), lock вокруг кэша/`_save()`, gzip (`Accept-Encoding`),
  учёт `Retry-After`, адаптивный бэкофф на 429/502/503, кэш пишется не чаще 2с,
  `flush()`, UA с контактом (URL репозитория), `maxlag=5` — уже в запросах exp2.
- `scripts/exp2_wikidata.py`: пул потоков (`--workers`, по умолч. 3), результаты
  в исходном порядке, `maxlag=5` во всех запросах, `Http(..., min_interval=0.55)`.

## Математика цели
- 200 req/min = 60/200 = **0.3 с** между стартами.
- Гейт гарантирует верхнюю границу: старты не чаще `1/min_interval`, ретраи проходят
  через тот же гейт → превысить нельзя; `min_interval` никогда не опускается ниже
  `base_interval`.

## Задачи (порядок исполнения)

### 1. `scripts/exp2_wikidata.py` — CLI `--rpm`, интервал из него, ETA, дока
- Добавить `--rpm <int>` (по умолчанию **200**); принять существующие `--workers`
  и позиционный `limit`. `Http("wikidata", min_interval=60/rpm)` (при rpm=200 → 0.3).
- Прогресс-строка: показать измеренный rpm и ETA:
  `exp2: DONE/N rpm=~X/time ETA ...s interval=...` (rpm из статистики Http, см. задачу 2).
- Обновить docstring: цель 200 req/min, источник лимита (Wikimedia APIs/Rate limits,
  неавторизованный клиент с UA → 200 req/min), примеры запуска
  (`--rpm 200 --workers 3`, `--rpm 170` для запаса).

### 2. `scripts/common.py` — счётчики нагрузки в `Http` (для контроля скорости)
- Под lock вести счётчики: `fetches` (реально отправленных запросов), `errors`
  (429/503/502/timeout), `t_start`.
- Метод `stats()` → `{"fetches": n, "errors": m, "interval": min_interval}`.
- Счётчики нужны только для измерения фактического rpm (200 ≠ потребление, если
  много попаданий кэша или ошибок) — ничего в логику запросов не меняет.

### 3. `scripts/common.py` — не расслаблять интервал сразу после 429
- Сейчас `min_interval *= 0.9` на каждом успехе — на потолке 200 rpm это «дёргает»
  интервал вверх-вниз (овершутинг, риск повторных 429).
- Добавить `self._last_error`: не ранее чем через ~30с после последней ошибки
  начинать расслабление к `base_interval`. Не «умнее» нынешней логики,
  а только добавляет паузу перед восстановлением.

### 4. `scripts/common.py` — защита от двух параллельных прогонов (fcntl lock)
- Проблема: лимит 200 req/min — на процесс. Два одновременно запущенных exp2
  дадут ~400 req/min с одного IP (превышение капа) и будут гонять один файл кэша.
- В `Http.__init__` (или в `main()` exp2) взять исключительную блокировку
  `RESEARCH/cache/wikidata.lock` через `fcntl.flock(LOCK_EX|LOCK_NB)`; при занятости —
  выход с понятным сообщением. `flock` снимается автоматически при завершении
  процесса (в т.ч. по kill), исключая «висячие» lock-файлы. Окружение Linux.
- Не затрагивает другие эксперименты: lock привязан к имени кэша (`wikidata`).

### 5. CHANGELOG.md — краткая запись изменений (правило AGENTS #12)

## Решения
- Таргет: **200 req/min по умолчанию**, `--rpm` для запаса (решение пользователя).
- Формат результатов exp2 (`results/exp2_wikidata*.jsonl|_stats.json`) **не меняется** —
  правки только про скорость и контроль скорости.
- Затрагиваемые файлы: `scripts/common.py`, `scripts/exp2_wikidata.py`, `CHANGELOG.md`.
  Дубликаты в `experiments/01_wikidata_baselines/scripts/` не трогаем (по AGENTS #9/#10),
  о них сообщается.

## Риски и ограничения
- Лимит 200 req/min считается **на IP по всем хостам Wikimedia сразу**
  (wikidata + en.wikipedia). exp2 нужно запускать в одиночку; при параллельных
  экспериментах снижать `--rpm` пропорционально их числу.
- Прогон ~44 237 записей при холодном кэше ≈ 1.5–2.2 req/элемент ≈ 66–97 тыс.
  запросов ≈ **5.5–8 ч** на 200 rpm; на тёплом кэше — кратно быстрее (видно по rpm).
- Не исключены одиночные 429 на потолке — бэкофф (задача 3) поглощает их.
- Без правок не будут работать: бага нет, объём правок мал.

## Валидация
1. `python3 -m py_compile scripts/common.py scripts/exp2_wikidata.py`.
2. Холодный пилот: `python scripts/exp2_wikidata.py --workers 3 --rpm 200 200` —
   проверить: прогресс показывает rpm ~190–210, ~0 429, интервал стабилен ~0.3±0.1,
   результаты пишутся, кэш растёт, `flush` срабатывает.
3. Тёплый повтор: тот же прогон должен завершиться почти мгновенно (попадания кэша).
4. Деградация/безопасность: запустить второй экземпляр параллельно — должен
   отказаться стартом с сообщением о lock.
5. Регресс формата: диф сравнить первые ключи `results/exp2_wikidata_pilot.jsonl`
   с прошлым пилотом (формат не изменился).
6. Внести запись в `CHANGELOG.md`; показать `git diff --stat`.
