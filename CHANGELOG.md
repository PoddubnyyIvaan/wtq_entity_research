# CHANGELOG

## [unreleased]

### scripts/split_sample.py — разделение выборки на N равных частей (новый скрипт)
- Разрезает `samples/sample200.jsonl` на 6 непрерывных непересекающихся частей
  (размеры: пять по 7373 + одна 7372, |разность| ≤ 1), строки копируются
  байт-в-байт; выходы `samples/sample200_part1..6.jsonl`.
- CLI: `python3 scripts/split_sample.py [INPUT_JSONL] [N_PARTS]`; контроль
  размеров и сводка по `example_id`. Спецификация: `specs/split_sample.md`.

### scripts/exp2_wikidata.py — --input и --cache-name (прогон по частям с разных машин)
- Добавлены `--input PATH` (входной JSONL, по умолчанию
  `samples/sample200.jsonl`) и `--cache-name NAME` (имя HTTP-кэша/лок-файла в
  `cache/`, по умолчанию `wikidata`). Прежний CLI (`limit`, `--workers`, `--rpm`)
  не изменился; парсинг аргументов вынесен в `parse_args`.
- Изоляция кэша обязательна при нескольких машинах: `cache/wikidata.json`
  держит один глобальный `flock`, любые два прогона на общей ФС блокировали бы
  друг друга и затирали кэш. `--cache-name wikidata_partK` отвязывает лок и кэш
  по частям.

### RUNBOOK.md — инструкция по запуску частей exp2 (новый файл)
- Пошаговая инструкция: установка, разделение выборки, запуск части на своей
  машине, распределение `--rpm` по внешним IP и диагностика блокировок,
  проверка различия внешних IP через эхо-сервисы, сбор результатов.

### scripts/exp2_wikidata.py — tqdm-прогресс
- Прогресс переведён на tqdm-бар с постфиксом `rpm/interval/errors` (ETA и
  скорость считает tqdm). Если tqdm не установлен — фолбэк на прежние текстовые
  строки `exp2: DONE/N rpm=... ETA ...s interval=...s errors=...`, зависимости
  не обязательны.

### scripts/exp2_wikidata.py — контроль скорости (--rpm) и ETA
- Добавлен `--rpm` (по умолчанию 200 — потолок Wikimedia для неавторизованных
  клиентов с корректным UA); `Http("wikidata", min_interval=60/rpm)`.
- Прогресс-строка показывает измеренный rpm и ETA: `rpm=~X ETA ...s
  interval=...s errors=...` (rpm из статистики Http).
- Docstring обновлён: цель 200 req/min, источник лимита (User-Agent policy),
  примеры запуска.

### scripts/common.py — счётчики нагрузки и защита от параллельных прогонов
- В `Http` под lock ведутся `fetches` (реально отправленные запросы), `errors`
  (429/502/503/timeout) и `t_start`; добавлен `stats()` — для измерения
  фактического rpm (потребление ниже 200 при попаданиях кэша). Контракт
  `get_json` не менялся.
- Расслабление интервала после ошибки отложено: успех уменьшает `min_interval`
  только если с последней ошибки прошло ≥30 с (не «дёргается» на потолке).
- Исключительный `fcntl.flock(LOCK_EX|LOCK_NB)` на `cache/<name>.lock` в
  `Http.__init__`: второй параллельный прогон того же эксперимента завершается
  с сообщением. Lock привязан к имени кэша, другие эксперименты не затрагивает;
  освобождается автоматически при завершении процесса.

### scripts/exp2_wikidata.py — безопасное распараллеливание запросов к API
- Ячейки обрабатываются пулом потоков (по умолчанию 3, `--workers N`); результат
  собирается в исходном порядке, семантика эксперимента не меняется.
- В каждый запрос добавлен `maxlag=5` — при высокой нагрузке API тормозит наш
  скрипт вместо ошибок/бана.

### scripts/common.py — потокобезопасность Http (контракт get_json сохранён)
- Добавлен общий `threading.Lock`: кэш (чтение/запись/`_save`) защищён мьютексом.
- Пауза пересчитана как «глобальный гейт стартов»: старты запросов идут не чаще
  чем `min_interval`, но сетевой RTT параллельных вызовов перекрывается. Это и
  даёт ускорение без повышения суммарной частоты запросов (которая и приводит к
  429/бану).
- UA дополнен контактом (URL репозитория) — требование политики Wikimedia.
- Добавлены `Accept-Encoding: gzip` (с распаковкой) и учёт `Retry-After` на 429/503.
- `_save()` ужат: полный сброс кэша не чаще 1 раза в 2 с (устраняет O(n²) I/O на
  большом кэше), на ошибках сброс принудительный; добавлен `flush()`.
